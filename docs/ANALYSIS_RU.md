# Анализ приложения и направления развития

## Назначение

QSpectrumAnalyzer управляет внешней SDR-утилитой, получает последовательность
оценок мощности по частотным bins и показывает текущий спектр и историю во
времени. Это инструмент обзора диапазона, поиска сигналов, сравнения уровней и
наблюдения за активностью, а не демодулятор радиосигналов.

## Перенесённый функционал

| Область | Возможности Windows 11-версии |
|---|---|
| Источники | `soapy_power`, `hackrf_sweep`, `rtl_power`, `rtl_power_fftw`, `rx_power` |
| Сканирование | непрерывное и single shot, диапазон, bin size, interval, gain, PPM, crop, LNB LO |
| Спектр | текущая кривая, max/min hold, среднее, smoothing, persistence |
| Коррекция | отображение baseline и вычитание baseline из файла |
| Waterfall | история, уровни, цветовая шкала, общий zoom по частоте |
| Поиск | список пиков, порог мощности, группировка непрерывных полос |
| Рабочее место | переставляемые/скрываемые панели, сброс раскладки, сохранение параметров |
| Windows 11 | Qt 6, DPI scaling, светлая/тёмная системная тема, command bar, нативный title bar |

## Ограничения текущей архитектуры

- Backend запускается отдельным процессом. Поддержка зависит от установленной
  версии утилиты, SDR-драйвера и формата её вывода.
- Показываемый уровень обычно является относительным dB/PSD. Без калибровки
  тракта, антенны и усиления его нельзя считать точным dBm на входе.
- Peak detector использует локальные максимумы и абсолютный порог; изменение
  шумового пола может давать нестабильный список сигналов.
- Average накопительный, поэтому старые измерения со временем получают слишком
  большой вес. Для мониторинга лучше иметь sliding window и EMA.
- Waterfall хранится в RAM и не предназначен для длительной записи и повторного
  анализа больших сессий.
- Диагностика backend сейчас проверяет наличие команды, но не проводит полный
  тест драйвера, потока данных и пропускной способности USB.

## Что улучшать дальше

### Приоритет 1 — точность и повторяемость

1. Добавить калибровочный профиль: частотно-зависимая поправка dB, gain chain,
   потери кабеля и единицы dBm/dBFS.
2. Рассчитывать noise floor робастно (median/percentile), выводить SNR и искать
   сигналы по `noise floor + N dB`, с hysteresis и минимальной длительностью.
3. Явно показывать фактические RBW, шаг частоты, время sweep и dropped sweeps,
   полученные от backend, а не только запрошенные значения.
4. Добавить sliding average, exponential average и независимую кнопку сброса
   average/max/min hold без перезапуска сканирования.

### Приоритет 2 — длительный мониторинг

1. Записывать sweeps вместе с timestamp и метаданными в chunked HDF5/Zarr;
   добавить replay без подключённого SDR.
2. Ввести occupancy: доля времени выше порога по каналу/полосе, max/mean/SNR,
   heatmap за часы и экспорт отчёта CSV/PNG.
3. Сделать event recorder: запуск записи при появлении сигнала, pre-trigger
   buffer, журнал событий и уведомления.
4. Добавить bookmarks/channel plan с названием, заметкой, ожидаемой полосой и
   импортом/экспортом CSV.

### Приоритет 3 — эксплуатация

1. Мастер первого запуска: обнаружение SoapySDR-устройств, проверка backend,
   драйвера, USB throughput и понятный отчёт об ошибке.
2. Профили задач: FM broadcast, ISM, авиа, выбранный канал — с сохранением всех
   параметров визуализации и acquisition.
3. Подписанный MSIX/installer, автоматическая проверка обновлений и журнал
   диагностики, который можно приложить к обращению.
4. Для большой скорости — прямой SoapySDR acquisition API вместо текстовых
   процессов и decimation отрисовки для миллионов bins.

Оптимальный следующий релиз для практической пользы: адаптивный noise floor и
SNR, запись/replay, bookmarks и профили калибровки. Вместе они превращают
визуальный анализатор в воспроизводимый инструмент измерения и мониторинга.
